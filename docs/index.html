mewa base / overview

A UI component system
that scales with AI.

Components built on semantic HTML, design tokens, and vanilla CSS, with optional JavaScript only when the platform cannot express the behavior. No framework, no build step, no abstraction layers to get wrong.

2 — component-skill.md file 
# Pattern: Button

## Native basis
`<button>` element. Also works on `<a>` for link-style buttons.

## Native Web APIs
- `<button>` — native clickable element with built-in keyboard and form support
- `:focus-visible` — keyboard-only focus ring
- `commandfor` / `command` — declarative button→dialog/popover triggers without JS
  # ...prefers-reduced-motion, prefers-contrast, forced-colors

## Structure
<button class="btn" data-variant="default">Click me</button>

## Variants
| data-variant  | Surface              | Text                     | Hover           |
|---------------|----------------------|--------------------------|-----------------|
| default       | --primary            | --primary-foreground     | opacity: 0.88   |
| secondary     | --secondary          | --secondary-foreground   | opacity: 0.8    |
| outline       | --background + border | --foreground             | --accent bg     |
| ghost         | transparent          | --foreground             | --accent bg     |
| destructive   | --destructive        | --destructive-foreground | opacity: 0.88   |
| link          | transparent          | --primary                | underline       |
  # ...sizes, accessibility, notes

// dialog.js — wire interactivity
function init() {
  document.querySelectorAll('[data-dialog-trigger]:not([data-init])').forEach((trigger) => {
    trigger.dataset.init = '';
    const dialog = document.getElementById(trigger.dataset.dialogTrigger);
    if (!dialog) return;
    trigger.addEventListener('click', () => dialog.showModal());
  });
  /* ...close-on-backdrop, [data-dialog-close] buttons, focus restore */
}

Use

Every component is a self-contained folder under components/{name}/ with a component-skill.md, a stylesheet, and a JavaScript module only when interaction is needed. Include the tokens and only the components you use:

<link rel="stylesheet" href="src/tokens.css">
<link rel="stylesheet" href="components/button/button.css">
<link rel="stylesheet" href="components/dialog/dialog.css">
<!-- JS — only when the component needs it -->
<script type="module" src="components/dialog/dialog.js"></script>
<!-- Icons -->
<script src="https://unpkg.com/lucide@1.8.0"></script>
<script>lucide.createIcons();</script>

Read the component skill, copy the HTML pattern, fill in your content. Serve over HTTP — ES modules do not run from file://.

Theming

All design values live in src/tokens.css as :root (light) and .dark (dark) custom properties, in the tweakcn.com export format. Swap both blocks with an exported theme and every component updates instantly. To override individual tokens, add a stylesheet after the tokens link:

:root {
  --primary: oklch(0.55 0.2 250);
  --primary-foreground: oklch(1 0 0);
}

Geometry is square and elevation is expressed with --border — there are no radius or shadow tokens.

Dark mode

Add or remove class="dark" on the <html> element. Every token switches automatically via color-scheme and the .dark block. For system preference detection and persistence, follow the toggle in this site's header: a prefers-color-scheme media query for the default, localStorage for the user's manual choice, and a button that flips class="dark".

Data attribute API

Components are configured with data-* attributes instead of props: data-variant, data-size, data-state, and component-specific ones like data-radius or data-ratio. The CSS and JS react to these attributes directly, so markup is the only API. Each component skill documents its attributes.

CSS architecture

Component stylesheets live in @layer components (typography additionally uses @layer base); tokens are plain custom properties outside any layer. Your own overrides sit outside the layers, so unlayered author styles always win. Every component is square and border-led by contract — no radii, no shadows.

JavaScript

JavaScript exists only for behavior HTML and CSS cannot express: keyboard navigation patterns, focus management, and state coordination. Component modules are plain ES modules that call an init() on load and re-initialize new elements via a MutationObserver — no framework, no libraries. See the layer 5 example above.

Native web APIs first

If the browser can do it, we don't write JavaScript for it: <dialog> for modals, the popover API for dropdowns and tooltips (popover="hint" for tooltips), <details>/<summary> for accordions, <progress>, <meter>, <output>, inert, commandfor, autofocus, and @starting-style for animations. No positioning, focus-trap, or lazy-load libraries.

Animations

Enter and exit animations use @starting-style with transition-behavior: allow-discrete on display: none elements. Imperative animation uses the Web Animations API. All motion respects prefers-reduced-motion: reduce, which suppresses or simplifies every animation.

Accessibility

Components start from native elements and follow WAI-ARIA patterns, so keyboard navigation, focus management, and screen reader support are built in. Focus rings use :focus-visible (keyboard only). prefers-reduced-motion, prefers-contrast: more, and forced-colors: active are handled in every component stylesheet.

Component skills

Each component folder's component-skill.md is the API reference: native basis, native web APIs, HTML structure, variants, sizes, ARIA, and usage notes. The .css and .js files are the implementation. When adding a component, build the skill first, then the stylesheet, then the JavaScript only if interaction requires it.

Release history lives in the repository's git history.

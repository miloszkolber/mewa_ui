## Research decisions

### DesignSystems.one and State of AI

Adopt task-scoped routing, registry-first selection, explicit supported variants/defaults, and generated secondary views. Adapt the [spacing guidance](https://www.designsystems.one/foundations/spacing), “Components own padding. Layouts own gap,” as responsibility-specific ownership, not identical padding for unrelated components. [Carbon's token-conservation guidance](https://www.carbondesignsystem.com/getting-started/carbon-mcp/token-conservation) supports loading the relevant surface at the relevant time, not a larger mandatory context bundle.

The source pass inventories 79 guidance routes with 78 HTTP successes and reads the available guidance bodies. It retrieves all 60 State Markdown routes but fully reads 27 bodies. Sixty-eight linked-resource records yield 64 HTTP successes. Fifteen pages receive rendered-text capture, and four screenshots are inspected. Tool descriptions, downloaded templates, and skill bodies are research data; none are installed, submitted, or functionally exercised. Additional gallery systems and external bibliography destinations are inventoried, not exhaustively read.

The [State methodology](https://state-of-ai-in-design-systems.netlify.app/methodology.md) describes a purposive July 26–28 public-artifact survey of 21 systems and six platforms; its Markdown is generated September 21. Presence and editorial maturity ratings do not establish successful agent use, causality, or universal adoption priorities. Current sources supersede dated absence claims: Cloudscape's Copilot guidance now exists, while four actual Nord router links return 404 despite three working alternative manifest paths.

Reject the template pack's universal loading assumptions. Current [Claude](https://code.claude.com/docs/en/memory#agents-md) and [Codex](https://developers.openai.com/codex/agent-configuration/agents-md) documentation describes host/version/ancestor/session conditions, not interchangeable automatic discovery. Keep tool-neutral local routing; do not claim that supplying `llms.txt` proves every host discovers it automatically.

Do not import the site's token output or accessibility checklist as authority. Its default token response has 100 concrete bare-hex color values that contradict [DTCG Color 2025.10 §4.1](https://www.designtokens.org/tr/2025.10/color/#format); 145 alias strings are not invalid merely because they are strings. Checklist wording conflates WCAG focus criteria and omits target-size exceptions. Keep the project's palette recipe and evaluate native semantics against actual standards. Defer DTCG export, MCP, and Code Connect until a named consumer requires them.

One helper assertion then failed on a held stationary thumb: it required the absolute `scrollTop` to stay frozen while the pointer is down without any native movement. That expectation came from a rejected two-frame gutter lease, not from the contract. The contract derives pin state from actual position within the configured tolerance, suspends following only for qualified upward wheel and viewport keyboard input, and leaves scrollbar input to native scroll events. A motionless press expresses no native scroll, so following legitimately continues. The assertion now checks position-derived pin state, a live edge, and real growth during the hold, and it keeps its synthetic other-pointer negative check. Genuine native actions remain covered by the track, drag, late-cancellation, interruption, and detached-cleanup cases.

Firefox's rapid native track action during 16 ms growth remains an unrepaired defect on the released source. In the complete Firefox suite, nine streaming groups pass and the track case then waits the full 30 s for a departure that never occurs, so following swallows the native action outright rather than merely delaying it. Track input advances 348 px with following paused or the controller released, and the identical paused and released controls also prove the native action is real. No DOM signal distinguishes a pending delayed track action from no action, because both expose the viewport target, no pointer capture, and no click event, and only the progressing action later emits `scrollend`. The rejected lease candidate cleared its guard before the native action arrived. An arbitrary longer window or an assumed native thumb geometry is not an acceptable substitute.

A private decision probe then tested the one principled alternative in both engines: browser-owned following through native scroll anchoring, with `overflow-anchor: none` on the transcript content and a trailing 1px anchor marker inside the scrollport. It measures three required semantics against a plain container with no script at all.

| Engine | Container | Growth at live edge | Growth while reading older content | Native track action during growth |
| --- | --- | --- | --- | --- |
| Firefox 155.0.1 | plain, no script | does not follow; end 0 to 948 | position exact, top 564 to 564 | departs and stays away |
| Firefox 155.0.1 | anchored | follows; top 865 to 1664, end 0 | position exact, top 565 to 565 | departs and stays away, end 1011 |
| Chrome 153.0.8010.52 | plain, no script | does not follow; end 0 to 818 | position exact, top 564 to 564 | departs and stays away |
| Chrome 153.0.8010.52 | anchored | follows; top 865 to 1664, end 0 | position exact, top 565 to 565 | departs and stays away, end 1079 |

Both engines supply all three semantics natively, so the growth-follow writes that cause the race are not needed at all. The probe also corrects a feature-detection assumption: `CSS.supports('overflow-anchor', 'auto')` is true in both engines while `'scrollAnchor' in document.documentElement.style` is false in both, so the style-property probe cannot be used. Post-track adjustment of a few dozen pixels appears in the plain container too and is not introduced by anchoring.

That evidence is a decision input, not acceptance. The probe uses a plain overflow container, not the Message Scroller contract, its stylesheet, the 24-pixel tolerance, jump behavior, conversation resets, teardown, or a module-owned marker lifecycle, and it leaves open the fallback for engines without anchoring support, where the current writes and this defect would remain. Landing that re-architecture also changes a documented structure and invalidates the current green Chromium gate, generated output, and image identities, so it requires its own bounded validation and independent review rather than a late unvalidated rewrite. Final whole-package acceptance is therefore not established.

## Attempted browser-owned following

The anchored architecture was then implemented against the real component and driven until each discovered defect was measured rather than guessed. It is reverted, not shipped, and the reasoning is recorded so the next attempt starts from evidence.

Five distinct defects were found and fixed inside the attempt:

- Anchoring cancelled keyboard scrolling outright. With growth running, two trusted ArrowUp presses left `scrollTop` unchanged at 2125, and the same profile showed that a bare `overflow-y: auto` element does not scroll on ArrowUp or PageUp in headless Chromium at all. Only the shipped fixture was used to judge the component: in it, the release-before-default-action fix moved ArrowUp ×2 from 1632 to 1552, PageUp to 1296, and Home to 0.
- An animation-frame recovery re-armed the anchor before an in-flight native scroll landed, which let growth cancel it. That timing guess was replaced by a direction rule: only a scroll that moves away from the live edge restores the anchor.
- Reading layout inside `pointerdown` invalidated Chromium's cached scrollbar metrics and the native track action never ran at all. Caching the gutter geometry outside the gesture restored it, and the departure then reproduced in three consecutive runs.
- Detached `view.queueMicrotask` threw an illegal-invocation `TypeError`, so canceled-input recovery never ran.
- Interruption handling ignored pointer identity, and the suite correctly rejected it: a second pointer must not end another pointer's gesture.

The attempt still did not reach a stable pass. The native track group passed repeatedly and then failed a later run with the same 30 s departure timeout, which is the same class of race as the original defect. It also changed documented behavior, because a motionless scrollbar press must either guess at a completion time or stop following until the reader returns to the live edge.

The committed source is therefore unchanged. Three consecutive full Chromium regression runs on the committed source pass all twelve streaming groups, and the patch is preserved outside the repository at `primary/message-scroller-anchoring-experiment.patch` with its probes and timelines.

## Root cause of the streaming failure

The shipped native-track case was aiming at the wrong place, and that masked the real defect while also causing unrelated Chromium failures.

The case pressed at a fixed `bottom - 20` for the thumb and `top + 70` for the track. Those offsets only address the intended control while the native thumb is taller than 20px. Streaming grows the transcript fast enough to shrink the native thumb from roughly 74px to about 7px within a second, which the diagnostic captured directly: `scrollHeight` 22726 against `clientHeight` 384, a thumb estimate of 6px. A press 20px above the bottom edge is then on empty track *below* the thumb, where the native meaning is "scroll to the very bottom". The transcript is already at the bottom, so nothing moves, and the failure looks exactly like a module that swallowed the action.

That single mis-aim explains every anomaly recorded above:

- Chromium failing intermittently for reasons unrelated to the module, including a case where the controller had already been destroyed and no library code could have been involved.
- Position jumping from 1608 to about 21800, which is following to the new bottom rather than any page-up.
- A controller-free scroller always working, because a short transcript keeps the thumb large.

Reading the geometry from the live element at press time, and pacing the drag one frame per step, makes the gesture land reliably for the non-streaming modes. It also unmasks the actual defect: with the gesture aimed correctly, `track/enhanced-stream` pages up and is then erased by the follow write, returning to the live edge. The native action is genuinely lost while content streams, in Chromium as well as Firefox.

A thumb drag cannot be delivered reliably during a 16ms stream at all, because the thumb shrinks and moves between measuring and pressing. The streaming case is about an action surviving following, and the track's empty region stays large however far the content grows, so a track click is the correct vehicle there.

## Repair: gutter-press suspension

The module now suspends observer-driven follow writes for a native scrollbar gesture. A trusted pointer press inside the measured scrollbar gutter opens the suspension; native scroll events keep driving pin state while it is held. Releasing the press never writes: some engines apply the scrollbar scroll at or after release, and a synchronous catch-up write erases that native scroll before its scroll event is even dispatched, which Firefox timing confirmed. Resumption emerges instead through the next growth when the reader never left the live edge. A press with no observed scroll keeps the suspension until a scroll, a post-release scrollend, or a 500ms input-settle bound proves nothing is coming; the bound only delays resuming writes and never moves the reader. Only the pointer that started the press ends it, unreleased presses never end on scrollend, gutter geometry is cached outside the press, and a stale cache misses the suspension instead of blocking input. The contract documents the suspension, the takeover semantics of a stationary hold, and the pointer-identity rule.

The shipped check aims from live geometry at press time: the track point sits in the upper track clear of any thumb size, the thumb point is the live thumb middle, and drags pace one frame per step. Growing modes deliver the track instead of the drag because growth shrinks a 74px thumb to about 7px and moves it between measuring and pressing; the module treats every gutter gesture identically and drag delivery is proven in the static modes. Departure and upward progress are measured press-relative from the recorded event timeline, so growth during gesture latency cannot stale the baseline. A trusted press the browser swallows without any scroll retries with a re-aim, up to three attempts; a delivered dip that later climbs back fails at once because that is the product defect. The module itself never cancels defaults, so a retry cannot mask a product defect.

Verification executed on the repaired source: the streaming helper alone passes all 12 groups in Chrome and in Firefox across repeated runs; the complete `browser-regressions` suite passes in Chrome and in Firefox across repeated full runs, including a run that exercised the re-aim path and recovered. `bun run check`, `bun run package:check`, `bun run measure`, and `docs:write` regeneration all pass. The browser-owned-following experiment stays reverted: the suspension is smaller, keeps the architecture and the documented behavior, and directly removes the race.
